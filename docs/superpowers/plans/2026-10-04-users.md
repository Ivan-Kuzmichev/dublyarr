# Пользователи Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** несколько учёток с общей библиотекой: админ (всё) и пользователи с правами, заданными админом; у каждого свои «Безопасность» и «Уведомления» (свой чат Telegram).

**Architecture:** роль и права — поля `users`; проверка — `can(user, perm)` в `src/lib/auth/permissions.ts`, на сервере через `requirePermission`/`requireAdmin` (`src/lib/auth/current.ts`) в каждом server action и странице. Уведомления — очередь как была, доставка по получателям (`notification_deliveries`).

**Tech Stack:** Next.js 16, TypeScript, better-sqlite3 + Drizzle, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-04-users-design.md`

## Global Constraints

- Все тексты интерфейса — на русском; отказ — «Недостаточно прав».
- Права проверяются на сервере в каждом action/странице; скрытая кнопка — не защита.
- Права по умолчанию: `subscribe`, `search`, `answer` — вкл; `downloads`, `storage` — выкл. Админ — все.
- Нельзя выключить/удалить/разжаловать последнего активного админа; нельзя удалить себя.
- API (`/api/v1`) и токены — только админ.
- Миграция: существующие учётки — `admin`; `app_settings['telegram'].chatId` и `telegram.events` → первому админу.
- Версия 2.3.0. Каждый коммит заканчивается строками:
  ```
  Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01L8VBCG17W738yjV2zJDPu1
  ```

## Review Focus

1. Прямой POST server action без права (минуя интерфейс) — отказ (тест на каждое защищённое действие, Task 4).
2. Выключенный пользователь с живым сеансом — следующий запрос отказан (Task 2).
3. Уведомление с кнопками уходит пользователю без права `answer` — не должно (Task 5).
4. Кнопка Telegram из чата пользователя без права `answer` — игнор (Task 5).
5. Последний админ разжалует/выключит себя — отказ (Task 3).

### Task 1: Роли, права, миграция

**Files:** Modify `src/lib/db/schema.ts`; Create `src/lib/auth/permissions.ts`; миграция `drizzle/0024_*.sql` (+ перенос Telegram); Test `tests/unit/permissions.test.ts`.

**Interfaces — Produces:**
- `type Permission = 'subscribe' | 'search' | 'answer' | 'downloads' | 'storage'`; `PERMISSIONS: readonly Permission[]`; `PERMISSION_LABEL: Record<Permission, string>`.
- `DEFAULT_PERMISSIONS: Record<Permission, boolean>` (subscribe/search/answer — true).
- `can(user: Pick<User, 'role' | 'permissions' | 'disabled'>, p: Permission): boolean` — выключен → false; админ → true; иначе флаг.
- `isAdmin(user)`.
- Схема `users` += `role` (`admin`|`user`, default `'admin'` для миграции существующих, новые через код задают явно), `permissions` (json, default `{}`), `disabled` (bool false), `telegramChatId` (text), `notifyEvents` (json, nullable), `lastLoginAt` (ts). `subscriptions` += `addedBy` (int, `set null`).

- [ ] Тест: `can` для админа/пользователя/выключенного; `migrateTelegramChat` переносит чат и события первому админу и идемпотентна.
- [ ] RED → схема, `pnpm db:generate`. Настройка `telegram` хранится зашифрованной, поэтому перенос — в коде, а не SQL: `migrateTelegramChat(db)` (вызов в `getDb()` при открытии): у первого админа нет чата, а в `telegram` есть `chatId` — перенести в `users.telegram_chat_id`, `telegram.events` — в `users.notify_events`, из настроек убрать. Тест — на `testDb()`.
- [ ] GREEN, commit «feat(users): роли, права, миграция».

**Produces:** `requireAdmin()`, `requirePermission(p)` — редирект на `/` (страница) или `throw new Forbidden('Недостаточно прав')`; для actions — `assertPermission(user, p)` → `{ error: 'Недостаточно прав' }`-совместимо: `class Forbidden extends Error`. `validateSession` — выключенный → null (сеанс удаляется). `passwordStep` — выключенный → «Учётка выключена»; успешный вход → `lastLoginAt`. `resetPassword(db, { username?, ... })`.

- [ ] Тесты: выключенный — вход отказан, живой сеанс недействителен; CLI `--user` сбрасывает нужную учётку, без `--user` — первого админа, неизвестный логин — ошибка.
- [ ] RED → GREEN → commit.

**Produces:** `recipients(db, kind)` — пользователи с чатом, событие включено (`notifyEvents ??
