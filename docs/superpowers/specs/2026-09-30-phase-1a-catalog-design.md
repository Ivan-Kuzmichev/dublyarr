# Фаза 1a «Каталог»: дизайн

Первая из четырёх частей фазы 1 (1a каталог → 1b подписки и студии → 1c поиск и разбор → 1d загрузки).
Источник правды по поведению — `docs/spec.md`; здесь — как именно делаем каталог.

## Цель

Сериалы и аниме из TMDB в локальной базе: найти, посмотреть карточку с сезонами и сериями и датами эфира,
держать данные свежими. На этом строятся подписки (1b), поиск раздач (1c: названия и альтернативные названия)
и календарь (1d: даты эфира).

## Что входит

- Клиент TMDB, ключ в мастере первого запуска и в настройках.
- Таблицы `titles`, `seasons`, `episodes`; определение «аниме»; ручная смена типа.
- Ежедневное обновление сериалов из базы (воркер).
- Прокси и кэш постеров и фонов.
- Экраны: «Поиск и тренды» (рисуется в коде по токенам), «Карточка сериала» (по `Series.dc.html` и `MobileSeries.dc.html`, без загрузок).

## Что не входит

- Фильмы: не показываются в поиске до фазы 3 (решение владельца).
- «Библиотека» — в 1b, когда появятся подписки.
- Статусы загрузки серий, колонки озвучек и блок подписки в карточке — 1b/1d; блоки «прогноз» и «скорость студий» — фаза 2.

## Решения

### Данные

`titles`:
- `id` (внутренний), `tmdb_id` (уникальный), `kind`: `series` | `anime`, `kind_manual` (bool — тип задан руками, обновление не трогает);
- `name_ru`, `name_original`, `original_language`, `alt_names` (JSON-массив строк: альтернативные названия TMDB для RU/US/GB/JP + латиница для аниме), `year` (первый эфир);
- `status`: `returning` | `ended` | `canceled` | `in_production` | `planned` (из TMDB `status`);
- `overview`, `genres` (JSON), `origin_countries` (JSON), `networks` (JSON: имя), `poster_path`, `backdrop_path`;
- `next_air_date`, `last_air_date`, `refreshed_at`, `created_at`.

`seasons`: `title_id`, `number` (0 = спецвыпуски), `name`, `air_date`, `episode_count`, `poster_path`.
`episodes`: `title_id`, `season`, `number`, `name`, `air_date` (дата, `YYYY-MM-DD`), `runtime` (мин). Уникальность `(title_id, season, number)`.

В базу сериал попадает, когда пользователь открыл его карточку (upsert деталей и всех сезонов). Карточки, на которые
не подписались, живут в базе и тоже обновляются; уборка неиспользуемых — позже, когда будут подписки (1b).

### Аниме

`kind = anime`, если в жанрах TMDB есть «Анимация» (id 16) и в `origin_country` есть `JP`. Иначе `series`.
Пользователь может переключить тип в карточке («Сериал / Аниме»); тогда `kind_manual = true`, и ежедневное обновление тип не меняет.
Тип нужен в 1b (профиль по умолчанию) и 1c (нумерация, романдзи).

### Клиент TMDB

- API v3, ключ v3 (`api_key`) или токен v4 (`Authorization: Bearer`) — принимаем оба: строка длиной 32 hex — v3, иначе токен.
- Язык `ru-RU`; если у сериала/серии пустое название или описание — дозапрос `en-US` только для недостающего.
- Детали: `/tv/{id}?append_to_response=alternative_titles,external_ids`; сезоны: `/tv/{id}/season/{n}` для каждого сезона.
- Поиск: `/search/tv?query=…&include_adult=false`; популярное: `/trending/tv/week`.
- Кэш ответов поиска/трендов в памяти процесса на 1 час (главная и поиск не дёргают TMDB на каждый заход). Детали не кэшируются — пишутся в БД.
- Таймаут 10 с; 429 — одна повторная попытка через `Retry-After` (не больше 5 с).
- Необязательный HTTP(S)-прокси (`http://host:port`): для API и картинок, через `undici.ProxyAgent`.
- Ключ и прокси — в `app_settings` (`tmdb`, зашифровано): `{ apiKey, proxy? }`.
- Ошибки на русском: «Неверный ключ TMDB» (401), «TMDB не отвечает: …», «TMDB ограничил запросы, попробуйте позже».

### Мастер и настройки

- Новый шаг мастера после аккаунта: **TMDB** (ключ, прокси необязательно, «Проверить» — запрос `/configuration`). Можно пропустить, но тогда поиск покажет «Добавьте ключ TMDB в настройках».
  Порядок: Аккаунт → TMDB → qBittorrent → Источники → Папки.
- Уже завершённый мастер не открывается заново; ключ меняется в «Настройки → Источники», карточка «TMDB» сверху раздела (остальной раздел — 1c).

### Обновление

Задача воркера `tmdb.refresh-all` раз в сутки (планировщик воркера: если последняя успешная была > 24 ч назад — поставить в очередь):
для каждого сериала в базе, у которого `status` не `ended/canceled` или `refreshed_at` старше 30 дней, — детали и сезоны,
начиная с последнего (остальные сезоны — только если изменилось `number_of_seasons`/`episode_count`).
Карточка при открытии обновляет сериал, если `refreshed_at` старше 12 часов (синхронно, с таймаутом; при ошибке показывает то, что в базе, и строку «TMDB не ответил, данные от <дата>»).

### Постеры и фоны

- Маршрут `/api/image/{size}/{file}` (size ∈ `w185`, `w342`, `w780`, `w1280`; file — имя из `poster_path`/`backdrop_path`, только `[A-Za-z0-9_-]+\.(jpg|png)`).
- Сервер отдаёт файл из `${DATA_DIR}/cache/images/{size}/{file}`; нет — скачивает с `image.tmdb.org` (через прокси, таймаут 15 с), сохраняет атомарно (tmp + rename), отдаёт с `Cache-Control: public, max-age=31536000, immutable`.
- Маршрут требует сеанс (как всё приложение).
- Не скачалось — 404; компонент `<Poster>` показывает цветную заглушку (как в макетах): цвет из палитры макетов, индекс = `tmdb_id % 18`, поверх — название.

### Экран «Поиск и тренды» (`/discover`)

Нарисовать в коде по токенам, показать скриншоты владельцу, затем доводить.
- Сверху поле поиска (debounce 400 мс, от 2 символов; запрос в URL `?q=` — страница работает по прямой ссылке).
- Результаты поиска — сетка постеров (desktop 6 в ряд, телефон 3): постер 2:3, название, год, тип «Аниме» бейджем.
- Без запроса: «Популярное за неделю» (тренды TMDB, сериалы) и «Скоро новые сезоны» — сериалы из базы со статусом `returning` и `next_air_date` в ближайшие 60 дней
  (в 1a список будет пустым почти всегда — показываем блок только при наличии данных).
- Клик по постеру — `/series/{tmdbId}` (карточка по TMDB id: если сериала ещё нет в базе — загрузить и сохранить).
- Без ключа TMDB — карточка «Добавьте ключ TMDB» со ссылкой в настройки. Ошибка TMDB — строка danger над сеткой.

### Экран «Карточка сериала» (`/series/[tmdbId]`)

По `Series.dc.html` / `MobileSeries.dc.html`, то, что есть в 1a:
- Hero: фон (`backdrop`, затемнение), постер, строка «Оригинальное · год · жанры · N сезонов · статус», заголовок.
  Кнопки: «Подписаться» (в 1a неактивна: «Подписки — в следующем обновлении»), «Обновить из TMDB», переключатель типа «Сериал / Аниме».
- Вкладки сезонов «Сезон N · M серий» (спецвыпуски — последней вкладкой «Спецвыпуски»), по умолчанию — последний вышедший сезон.
- Таблица серий: №, название, дата эфира («8 сент», «через 6 дн» для будущих); вышедшие — обычным цветом, будущие — `faint`.
  Колонок озвучек и статусов в 1a нет.
- Описание (`overview`) под hero.
- Мобильная версия — по `MobileSeries.dc.html`: hero в одну колонку, сезоны — горизонтальная прокрутка чипов.

## Ошибки и крайние случаи

- TMDB недоступен при открытии уже сохранённого сериала — показываем базу + предупреждение; не сохранённого — «Не удалось загрузить из TMDB» и кнопка «Повторить».
- У сериала нет русского названия — показываем оригинальное; `name_ru` хранит то, что вернул TMDB для `ru-RU` (TMDB подставляет оригинал, если перевода нет).
- Сезон без серий (анонсирован) — вкладка есть, в таблице «Серии ещё не объявлены».
- Сериал удалён из TMDB (404 при обновлении) — остаётся в базе как есть, `refreshed_at` не обновляется, в логах предупреждение.

## Тесты

- Unit: разбор ответа деталей/сезона TMDB в строки БД (на сохранённых реальных JSON в `tests/fixtures/tmdb/`), определение аниме,
  ручной тип переживает обновление, выбор v3/v4 авторизации, дозапрос `en-US` для пустых полей, 401/429/таймаут.
- Unit: кэш картинок — первый запрос качает и сохраняет, второй отдаёт с диска без сети; неверное имя файла — 400; ошибка скачивания — 404.
- Unit: планировщик `tmdb.refresh-all` — ставит задачу раз в сутки, какие сериалы обновляются.
- E2E: мастер с шагом TMDB (пропуск), поиск → карточка через подменённый TMDB (e2e-сервер получает `TMDB_BASE_URL`/`TMDB_IMAGE_BASE_URL`, указывающие на локальную заглушку с фикстурами).
