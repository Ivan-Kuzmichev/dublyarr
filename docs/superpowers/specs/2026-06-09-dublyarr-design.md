# Dublyarr — дизайн-спека (M1–M4)

Дата: 2026-06-09. Статус: согласовано в брейншторме.

## 1. Что это

**Dublyarr** — self-hosted веб-сервис «всё в одном» класса Sonarr/Radarr для фильмов и сериалов с главной отличительной фичей: **выбор озвучки (студии)** при отслеживании. Работает поверх уже существующей инфраструктуры пользователя: Jackett (поиск по трекерам, сейчас настроен RuTracker) и qBittorrent (скачивание). Метаданные — TMDb (ru-RU).

Подтверждено прототипом (CLI-скрипт в этом репо): озвучки надёжно извлекаются из **описания** раздач RuTracker (формат `VO (Сыендук) + MVO (TVShows, HDrezka) + Sub (Rus, Eng)`), а для специализированных трекеров (LostFilm, AniLibria…) студия равна имени трекера.

### Не входит в M1–M4 (отложено в M5+)

RSS-мониторинг, уведомления (Telegram и т.п.), статистика, мультипользовательность, импорт существующей библиотеки, поддержка иных торрент-клиентов.

## 2. Майлстоуны

- **M1 — фундамент и просмотр**: скелет проекта, БД, настройки, поиск TMDb, страница тайтла с доступностью озвучек (порт парсера), UI-каркас.
- **M2 — отслеживание и ручное скачивание**: добавление в отслеживание, пресеты качества, выбор озвучки, ручной grab → qBittorrent → импорт в библиотеку.
- **M3 — автоматика**: воркер с cron-тиком, конвейер авто-поиска/скачивания/апгрейда, календарь, активность, blacklist.
- **M4 — auth и деплой**: вход по паролю + LAN без пароля, Docker-образ, GitHub Actions, релизы.

Версии: semver, `0.1.0` на M1 → `1.0.0` на M4.

## 3. Архитектура

Вариант B: **Next.js + отдельный воркер-процесс**, один репозиторий, общий код.

```
apps/web      Next.js (App Router, RSC) — UI + API routes
apps/worker   Node-процесс — cron-тик, конвейер, поллинг qBittorrent
packages/core БД (Drizzle + SQLite), парсер релизов, скоринг,
              клиенты Jackett/TMDb/qBittorrent, шаблоны имён
```

- SQLite в WAL-режиме — одна БД, два процесса, конкурентный доступ безопасен.
- Воркер живёт независимо от UI: пересборка/рестарт Next.js не убивает мониторинг.
- В Docker — один образ, два процесса под лёгким node-супервизором.

### Стек

| Слой | Выбор |
|---|---|
| Фреймворк | Next.js (App Router, RSC) + TypeScript |
| Стили | **Чистый CSS** — CSS Modules + глобальные CSS-переменные темы. Без Tailwind и UI-китов; свои компоненты (карточка, бейдж, селект, табы, модалка) |
| Данные на клиенте | TanStack Query |
| БД | SQLite + Drizzle ORM, миграции применяются на старте |
| Логи | pino |
| Тесты | Vitest (unit/integration) + Playwright (e2e) |
| Язык UI | Русский |

## 4. Модель данных (SQLite + Drizzle)

```
titles                       ← фильм или сериал
  tmdb_id, type (movie|tv), title_ru, title_original, year,
  poster_path, overview, tmdb_status, tracked (bool),
  quality_preset_id → quality_presets,
  voiceover            ← выбранная студия ("Сыендук" | "any")
  monitor_rule         ← all | future_only | manual
  root_folder

episodes                     ← для сериалов, синк из TMDb
  title_id, season, episode, air_date, name_ru,
  wanted (bool)         ← флаг «надо скачать» (выбор по сериям)
  file_id → files       ← null = ещё не скачана

files                        ← скачанное на диске
  title_id, episode_id?, path, size,
  quality_source, quality_resolution, voiceover_studio,
  release_guid, downloaded_at

quality_presets
  name, allowed (json: галочки по глобальной лестнице качеств),
  preferred (qualityKey), upgrade_enabled (bool)

downloads                    ← очередь + активные
  title_id, release_guid, qbit_hash, episodes_covered (json),
  status (queued|downloading|completed|failed|imported),
  progress, error

studio_aliases               ← "Сыендук" ← ["Syenduk", "SyenDuk"]
tracker_studio_map           ← "LostFilm.tv" → "LostFilm"
history                      ← аудит: search/grab/import/upgrade/fail
blacklist                    ← битые раздачи, не пробовать снова
settings                     ← key-value: токены, urls, интервал крона,
                               шаблоны имён, прокси, auth hash
```

Ключевые решения:

- **Эпизоды храним в БД** (как Sonarr) — это даёт календарь, выбор по сериям и точный статус «что докачать». Ежедневный TMDb-синк; при `monitor_rule=future_only` новые серии появляются с `wanted=true`.
- У каждого файла записаны **озвучка и качество** — смена озвучки тайтла не трогает старые файлы; новые серии качаются уже в новой озвучке.
- Лестница качеств глобальная и фиксированная: BDRemux 2160p > WEB-DL 2160p > BDRemux 1080p > BluRay 1080p > BDRip 1080p > WEB-DL 1080p > WEBRip 1080p > HDTV 1080p > 720p…

## 5. Модель озвучки

- **Простой селект** на странице тайтла: конкретная студия или «Любая русская» (fallback). Никаких приоритетных списков.
- Список доступных студий для тайтла строится из распарсенных раздач Jackett (таблица «Доступные озвучки»: студия, тип VO/MVO/DVO/AVO, сезоны, качества, число раздач).
- Озвучку можно **сменить в любой момент**: старые файлы остаются, новые серии качаются в новой озвучке. Кейс: выбранная студия не озвучила новый сезон → зашёл на карточку, переключил.
- Парсер (порт `src/parser.mjs` на TS, поведение зафиксировано фикстурами):
  - источник текста: description, если он длиннее title и содержит кириллицу (RuTracker);
  - виды: `VO|MVO|DVO|AVO (...)`; `Sub (...)` — субтитры, не озвучка;
  - нормализация через `studio_aliases`; для специализированных трекеров — `tracker_studio_map`;
  - также парсятся сезоны («Сезон: 1-2», SxxEyy, диапазоны) и качество (source + resolution, канонический регистр).

## 6. Пресеты качества

- Именованные пресеты (например «4K», «FullHD»), редактируются в настройках: чекбоксы по глобальной лестнице.
- **Предпочитаемое** = самое высокое из отмеченных по умолчанию; можно переопределить селектом.
- `upgrade_enabled`: если скачано качество ниже предпочитаемого — при появлении лучшей раздачи докачиваем и **удаляем старый файл**.

## 7. Конвейер воркера (cron-тик)

Интервал тика — из настроек (по умолчанию 15 мин, диапазон 1–1440). Обнаружение релизов — **polling** (вариант A; RSS отложен в M5).

```
тик каждые N минут:
1. Выбрать тайтлы: сериалы с wanted-эпизодами без файла,
   фильмы tracked без файла (для вышедших по TMDb),
   ИЛИ файлы ниже preferred при upgrade_enabled
   (рейт-лимит: один тайтл ищем не чаще раза в час)
2. Jackett search по title_original
3. Парсинг релизов (parser из packages/core)
4. Фильтр: озвучка совпадает + качество в allowed +
   сезон/серия покрыты + сиды ≥ min + не в blacklist
5. Скоринг: ближе к preferred → выше; tie-break: сиды
6. Grab: magnet/torrent → qBittorrent API
   (category=dublyarr, save path=staging)
7. Поллинг прогресса (тот же тик + страница «Активность»)
8. Завершилось → import: hardlink/move в библиотеку по шаблону
   имён, запись в files, эпизоды закрыты, history-запись
9. Upgrade: новый файл выше качеством → import → старый удалить
10. Зависло/битое (таймаут настраиваемый) → blacklist →
    следующий кандидат
```

- **Сезонные паки**: раздача «сезон целиком» закрывает все wanted-серии сезона; маппинг файлов внутри пака — парсингом имён (SxxEyy).
- Структура библиотеки — конвенции Plex/Jellyfin; шаблон имён настраивается:
  `{Show}/Season {ss}/{Show}.S{ss}E{ee}.{Quality}.{VO}`.

## 8. UI

Тёмная тема. 6 страниц. Десктоп: **верхняя навигация** (логотип · Отслеживаемое · Поиск · Календарь · Активность с бейджем счётчика · ⚙️ справа).

**Адаптив обязателен.** Мобильный: **нижний таб-бар** (Отслеживаемое / Поиск / Календарь / Активность; настройки — иконкой в шапке). Сетка постеров 6 → 4 (планшет) → 3 (телефон) колонок; hero тайтла складывается в колонку; таблица озвучек → карточки; вкладки настроек — горизонтальный скролл.

### Страницы

1. **Отслеживаемое** — секции «Сериалы» / «Фильмы», постер-карточки с бейджами поверх постера:
   - верх-лево: тип (TV/Фильм, красный); верх-право: качество скачанного (целевое серым, если не скачано);
   - низ-лево: озвучка (зелёный); низ-право: статус — ✓ скачано · ⬇ % (+полоска прогресса) · ⏳ ожидание;
   - под постером: название, год · контекст (текущая серия / завершён / ждёт сезона).
   - Карточки «+» нет — **добавление только через поиск**.
2. **Поиск (TMDb)** — поле по центру, результаты карточками (рейтинг TMDb, тип, статус); на уже отслеживаемых — бейдж «✓ отслеживается». Клик → страница тайтла.
3. **Тайтл** — hero (постер, названия, статус, жанры, описание); блок отслеживания: селект озвучки, селект пресета качества, monitor_rule, кнопка «Искать сейчас»; таблица «Доступные озвучки»; сезоны с чекбоксами серий и статусом каждой; список файлов (с удалением).
4. **Календарь** — агенда по датам: серии (с состоянием «вышла на ТВ · ждём раздачу в {студия}» / «выйдет в эфир») и цифровые релизы фильмов из TMDb.
5. **Активность** — активные загрузки (прогресс, скорость, источник) + история (скачано / grab / не найдено / ошибки).
6. **Настройки** — вкладки: Качество (редактор пресетов) · Озвучки (алиасы студий, маппинг трекер→студия) · Интеграции (Jackett, TMDb, qBittorrent, прокси) · Папки и имена (root folders, шаблоны) · Мониторинг (интервал крона, таймауты, мин. сиды) · Безопасность (пароль, LAN без пароля).

## 9. Auth (M4)

Один пользователь. Вход по логину/паролю (hash в settings), сессия — подписанная cookie. Опция «LAN без пароля»: запросы с приватных адресов (RFC1918) пропускаются без логина. Middleware Next.js защищает все страницы и API.

## 10. Деплой и релизы (M4)

- **Один Docker-образ**: Next.js + воркер, два процесса под node-супервизором. Публикация в **ghcr.io**.
- **GitHub Actions**:
  - `ci.yml` — push/PR: lint, typecheck, Vitest, Playwright, сборка;
  - `release.yml` — на тег `v*`: сборка образа → push в ghcr (`1.2.0`, `1.2`, `latest`) → GitHub Release с автогенерированным changelog.
  - Релиз = `git tag v1.2.0 && git push --tags`.
- `docker-compose.yml` в репо: сервис + volume для SQLite/конфига; Jackett и qBittorrent — внешние (адреса в настройках). В README — опциональный полный compose со всем стеком.
- Обновление: `docker compose pull && docker compose up -d`; миграции Drizzle — автоматически на старте.

## 11. Тестирование

- **Unit (Vitest)** — ядро без сети: парсер озвучек/качества/сезонов (фикстуры из реальных ответов Jackett, включая 50 раздач Rick and Morty), скоринг, маппинги, шаблоны имён.
- **Integration (Vitest)** — API-роуты и конвейер против реальной SQLite (temp-файл, не моки БД) с записанными HTTP-фикстурами Jackett/TMDb/qBittorrent.
- **E2E (Playwright)** — поиск → добавление → смена озвучки → статусы; прогон и в мобильном вьюпорте (таб-бар, адаптив).
- Всё гоняется в CI на каждый push.

## 12. Обработка ошибок

- Внешние API (Jackett/TMDb/qBittorrent) недоступны → запись в history, ретрай на следующем тике; UI показывает статус интеграций в настройках.
- Битые/зависшие раздачи → таймаут → blacklist → следующий кандидат по скорингу.
- Раздач в выбранной озвучке нет → статус «⏳ ждём раздачу в {студия}» на карточке и в календаре; поиск продолжается каждый тик (с рейт-лимитом).

## 13. Судьба текущего кода

CLI-прототип (`src/*.mjs`, `scripts/`, `reports/`) после старта реализации удаляется; **логика `src/parser.mjs` портируется в `packages/core`** вместе с наработанными фикстурами. `.env`-ключи переезжают в настройки сервиса.
