# Фаза 4 «Laya»: дизайн

Источник правды — `docs/spec.md` §3 (разбор, финальная проверка), §13 (Laya); CLAUDE.md («Laya не генерирует текст… всё работает и без неё»);
макеты — `Settings.dc.html` (раздел «AI»), `AiTraining.dc.html`, `MobileAiTraining.dc.html`.

Laya — открытая модель решений Convai Innovations (Apache-2.0): пакет `laya` (Python ≥ 3.10), чекпойнт `laya-multilingual`
(mmBERT-base, 322M, 100+ языков). Вопросы трёх типов — `choice` (выбор), `noul` (да/нет, P(true)), `score`; ответы с откалиброванной вероятностью.

## Решения владельца

- **Python-сервер в образе** (официальный пакет), а не Node-рантайм `@receptron/laya` (у него нет многоязычной ONNX-модели).
- **Модель скачивается при первом запуске** в `/data/laya/base` (Hugging Face, через прокси TMDB, если задан); пока не скачана — всё работает без Laya.
- **Дообучение — лёгкий адаптер**, а не переобучение самой модели (на Celeron это нереально): Laya не меняется, по ответам пользователя
  учится маленькая надстройка (логистическая регрессия) для каждой задачи. Версии, проверка «не хуже», откат — как в spec §13.
- **NAS — Celeron (J4125/N5105), 4–8 ГБ**: модель запускается в ONNX INT8, если это работает, иначе — PyTorch на CPU.

## Что не входит

- Генерация текста (никогда). Дообучение самой модели (RLCD). Выбор модели и адреса в интерфейсе.

## 1. Запуск

`laya/serve.py` (Python 3.11, venv в образе: `laya[onnx]`, PyTorch CPU) — дочерний процесс супервизора на `127.0.0.1:${LAYA_PORT}`:
- при старте: модель есть в `/data/laya/base` — загрузить; нет — скачать (`huggingface_hub.snapshot_download`, ревизия закреплена в коде), состояние `downloading`;
  после скачивания — экспорт ONNX INT8 (если пакет умеет) в `/data/laya/base/onnx`; не вышло — PyTorch.
- `GET /health` → `{ status: 'downloading' | 'loading' | 'ready' | 'error', runtime: 'onnx-int8' | 'torch', laya: '0.3.x', model: '<ревизия>', error? }`;
- `POST /ask` `{ state, questions }` → ответы `laya.predict` как есть (choice + распределение, noul P(true), score) и `ms`; один запрос за раз (очередь).
- Прокси — `HTTPS_PROXY` от супервизора (прокси TMDB из базы). Память ограничена одним загруженным чекпойнтом.
- `dublyarr laya-bench` (CLI): 20 вопросов из набора «тот ли сериал» → среднее и p95 времени; результат пишется в `app_settings['laya.bench']`.

Node: `src/lib/laya/client.ts` — `layaHealth()`, `layaAsk(state, questions, { timeoutMs })` (таймаут 10 с; ошибка → «недоступна»), статус в «Сервисах» по `/health`.

## 2. Задачи

Настройка `app_settings['laya']`: `{ tasks: { studio, match, anime, final }: boolean (все вкл.), threshold: 0.85 }`.
Общий слой — `decide(db, task, input)`: вопрос к Laya → признаки → адаптер текущей версии → `{ answer, p, by: 'laya' }`, иначе (Laya выключена/недоступна/задача выключена)
`{ by: 'rules' }` — поведение как до фазы 4. Ответ кэшируется (`laya_answers`: задача, ключ входа, версия адаптера), повторные поиски не спрашивают заново.
Бюджет — не больше 20 вопросов к Laya за проход поиска одного сериала (CPU NAS).

| Задача | Когда | Вопрос | Решение при p ≥ порога | Ниже порога |
|---|---|---|---|---|
| **Какая студия** (`choice`) | у раздачи есть озвучка, студия не распознана словарём («Неизвестная студия») | заголовок, теги, трекер → выбор из ≤ 19 студий словаря подходящего вида + «новая» | подпись — вариант написания студии, студия помечается «добавила Laya, не подтверждено» | «Неизвестная студия» (как сейчас) |
| **Тот ли сериал** (`noul`) | совпадение «сомнительно» (0,5–0,8) | названия, год, сезоны сериала; заголовок, размер | «да» — как совпадение; «нет» (P(true) ≤ 1 − порог) — отказ | «Сомнительное совпадение» → вопрос |
| **Нумерация аниме** (`choice`) | сквозной номер не раскладывается по TMDB однозначно (номер больше известных серий или сезонов несколько) | заголовок, сезоны с числом серий → выбор из 2–4 вариантов (сезон, серия) | выбранный вариант | эвристика как сейчас |
| **Финальная проверка** (`noul`) | перед стартом загрузки (серия, пак, фильм) | «Это S01E03 сериала X в озвучке Y?»: заголовок, теги, размер, файлы (если известны) | качаем | следующая раздача по рейтингу, не больше 3; ни одна — вопрос пользователю |

Laya недоступна — финальной проверки нет (качаем), остальное — правила и вопросы, как сейчас.

## 3. Примеры

Таблица `laya_examples`: `task`, `input` (JSON: state + варианты), `label` (ответ пользователя), `laya` (что ответила Laya, p), `source`
(`match-answer` | `studio-assign` | `studio-confirm` | `telegram` | `final-reject` | `correction`), `created_at`. Источники:
«Это он» / «Не тот сериал» (ручной поиск и Telegram), «Назначить студию», подтверждение/отклонение студии от Laya в словаре,
«ни одна не прошла финальную проверку» → ответ пользователя. Примеры — в бэкапе (они в базе).

## 4. Адаптер и версии

Адаптер задачи — логистическая регрессия по признакам: logit(p Laya), для `match` — оценка совпадения правил, для `studio` — совпадение с вариантами
написания (нормализованное расстояние), для `final` — отклонение размера от ожидаемого, смещение. Обучение — градиентный спуск в Node (секунды).
Ночью (окно из «Расписания»), если с прошлой версии ≥ 30 новых примеров (или «Обучить сейчас»): по каждой задаче — 80 % / 20 % (детерминированно по id),
метрики на отложенных — точность и log-loss текущей и новой версии; применяется, только если не хуже (по log-loss, при равенстве — точность).
Версия — `/data/laya/versions/<N>/adapters.json` + строка `laya_versions` (номер, дата, число примеров, метрики, доля «решает сама», версия `laya`, ревизия модели).
Хранятся 3 последние + «Базовая» (без адаптера). Откат — одной кнопкой. Обновление: `laya` или ревизия модели не совпадает с версией → базовая + переобучение
на всех примерах в ближайшее ночное окно (без порога 30).

## 5. Экраны

- **«Настройки → AI»** (`Settings.dc.html`): статус («Модель загружена · последний ответ 0,9 с» / «Скачивается…» / «Недоступна»), «Проверить»,
  блок «Дообучение» (накоплено N, +M с прошлого раза, ссылка), четыре переключателя задач, порог (50–99 %).
- **«Дообучение»** `/settings/ai/training` (`AiTraining.dc.html`, `MobileAiTraining.dc.html`): по задачам — примеры, точность, «решает сама»;
  последние примеры (раздача, вопрос, Laya · p, вы); версии с откатом, «Обучить сейчас»; правила (ночью, только если не хуже, 3 версии).
- **Словарь студий**: отметка «Laya, не подтверждено» и кнопки «Верно» / «Нет».

## Ошибки и крайние случаи

- Нет интернета при первом запуске — `downloading` с ошибкой, повтор раз в час; всё работает без Laya.
- Laya отвечает дольше 10 с — запрос отменяется, решение по правилам; три таймаута подряд — «недоступна» на 10 мин.
- Меньше 10 примеров по задаче — адаптер не обучается (базовая).
- Неполный ответ (нет нужного ключа) — как «недоступна» для этого вопроса.

## Тесты

Unit: клиент (ответы, таймаут, недоступна), `decide` (порог, выключенная задача, кэш, бюджет), каждая из четырёх интеграций (с подменённой Laya),
сбор примеров из каждого источника, адаптер (обучение, предсказание, разбиение, «не хуже»), версии (хранение 3, откат, несовместимость после обновления), ночная задача.
Образ: `docker build` + `scripts/laya-smoke.sh` в контейнере (скачать модель, ответить на вопрос, замер) — «laya smoke: OK».
E2E (`12-laya`): заглушка Laya (`LAYA_STUB=1` — детерминированные ответы) → сомнительная раздача решена Laya → «Дообучение» показывает пример после ответа пользователя.
