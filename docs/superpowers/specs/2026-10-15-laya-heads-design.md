# Дообученные «головы» Laya: дизайн

Laya (`laya-multilingual`) — энкодер ModernBERT + «головы» решений (`DecisionModel`: `head` — 2 слоя трансформера, `type_emb`, `scorer`, `act_head`).
Встроенного дообучения в библиотеке нет, но модель — обычный PyTorch, а `laya.load` грузит и свою папку. Дообучаем только головы на данных Dublyarr,
веса голов лежат в репозитории и попадают в образ; энкодер (основная часть, ~1,9 ГБ) по-прежнему скачивается с Hugging Face.

## Решения владельца

- Учим **только головы**, результат — **в репозитории**.
- Обучение — **на Mac владельца** (Apple M1 Pro, 32 ГБ; MPS), не в Docker.
- Должна быть «возможность подтянуть натренированную модель»: образ берёт головы из репозитория; можно отключить и вернуться к базовой.

## Что не входит

- Дообучение энкодера, своя модель вместо Laya.
- Обучение на NAS (там остаётся только адаптер поверх ответа, как сейчас).
- Новые задачи Laya — те же четыре: «тот ли сериал», «какая студия», «нумерация аниме», финальная проверка.

## 1. Данные (`src/lib/laya/dataset.ts`, `GET /api/v1/laya/dataset`)

Строка набора: `{ task, group, state, question, target }` — `state`/`question` строго как их отправляет Dublyarr (`matchInput`, `studioInput`, `animeInput`, `finalInput`),
`target` — `true/false` для «да/нет», ключ варианта для «выбора»; `group` — сериал (для разбиения без утечки).

Источники (по убыванию надёжности):
1. **Ответы пользователя** — `laya_examples` (уже хранят `input` и `label`).
2. **Решения пользователя** — `release_rules` (это он / не тот сериал) → `match` по раздачам этого правила.
3. **Скачанное** — раздачи импортированных загрузок → `match = да`, `final = да` (серия, озвучка и качество загрузки).
4. **Отрицательные пары** — раздачи сериала A, подставленные к сериалу B из библиотеки (другое название) → `match = нет`; раздача A с чужой студией в вопросе → `final = нет`.
5. **Студии** — раздачи с подписью, совпавшей со студией словаря (по варианту написания), → `studio = эта студия`; подписи, назначенные пользователем, — из `laya_examples`.

Баланс: отрицательных пар не больше, чем положительных, ×2; на один сериал — не больше 200 строк задачи (Чёрный клевер не перевешивает остальных).
Выгрузка — JSONL через API (только админ, только локальная сеть, как весь API).

## 2. Обучение (`laya-train/`, Python, на Mac)

- Окружение: `uv` + Python 3.11, `laya==0.3.22`, тот же `torch` (MPS), закреплённая ревизия модели — как в образе.
- Кодирование — внутренние функции Laya (`_check_question`, `_to_internal`, `_encode_state`, сборка батча как в `decide_batch`), чтобы вход совпадал с боевым.
- Учим: `scorer`, `type_emb`, `head` (2 слоя); энкодер заморожен (`detach_encoder=True`, без градиентов). Потеря — кросс-энтропия по вариантам (для «да/нет» — два варианта).
- Разбиение: 80 / 20 **по сериалам** (`group`), сид фиксирован. Эпохи — пока растёт качество на отложенной части (ранняя остановка), lr 1e-4, AdamW.
- После обучения — калибровка температуры Laya на отложенной части (`fit_temperatures`), чтобы «уверенность 85 %» значила 85 %.
- Принимается, только если на отложенной части **по каждой задаче** log-loss не хуже базовой и точность при пороге 0,85 (доля решённых сама × точность) не хуже.
  Иначе — отчёт, в репозиторий ничего не кладётся.

Результат: `laya/heads/heads.safetensors` (fp16, только веса голов и `temperature`) и `laya/heads/meta.json`
(`{ laya, model, revision, createdAt, examples, metrics: { task: { base, tuned } } }`).

## 3. Загрузка в образе (`laya/serve.py`)

- После `laya.load` — если есть `heads.safetensors` и `meta.model/revision/laya` совпадают с загруженной моделью, веса голов подменяются (`load_state_dict(strict=False)`, проверка, что подменились ровно ожидаемые ключи).
  Не совпадает версия — головы не грузятся, в журнал строка, работает базовая.
- `GET /health` → `model` с пометкой: `convaiinnovations/laya-multilingual@<rev>+heads-<дата>` — кэш ответов (`laya_answers` по модели) и адаптеры Node переключаются сами.
- Свои головы владельца — `${DATA_DIR}/laya/heads/` имеет приоритет над теми, что в образе.
- Настройка «Дообученная Laya» в «Настройки → AI» (по умолчанию включена): выключено — laya-serve грузит базовую. Переключение — перезапуск laya-serve супервизором.

## Ошибки и крайние случаи

- Файл голов битый / другие размеры — не грузится, журнал, базовая модель.
- Мало данных для задачи (< 50 строк в отложенной части): головы общие для всех задач, поэтому задача всё равно учится вместе с остальными, но в отчёте помечена «не проверено»; «принять» требует, чтобы не стали хуже проверенные задачи.
- Повторное обучение — тот же скрипт; новые головы заменяют файл в репозитории (история — в git).

## Тесты

Node: сборка набора (каждый источник, баланс, группы, формат совпадает с `*Input`), API `laya/dataset` (админ), настройка.
Python (`pytest` в `laya-train/`): кодирование совпадает с `agent.decide` (те же логиты до обучения), сохранение/загрузка голов (подмена ровно нужных ключей), отказ при несовпадении модели.
В образе: `LAYA_STUB=0` прогон `laya-bench` с головами и без — ответы есть, `model` с пометкой `+heads`.
