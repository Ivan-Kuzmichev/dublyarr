# Пользователи: дизайн

Dublyarr был сервисом для одного пользователя (spec §14). Владелец решил: несколько учёток с общей библиотекой,
первая учётка — администратор, права остальных задаёт администратор.

## Решения владельца

- **Администратор** — первая учётка (созданная при первом запуске) и все, кого админ сделает админом. Админу доступно всё, как сейчас.
- **Пользователь** — права задаёт админ флагами. В настройках у пользователя только «Уведомления» и «Безопасность» (без блока API).
- **Библиотека, подписки, загрузки — общие.** У подписки видно, кто её добавил.

## Что не входит

- Свои подписки, свои профили или своя медиатека у каждого.
- Учёт просмотров (CLAUDE.md — никогда).
- Самостоятельная регистрация: учётки создаёт только админ.
- API для пользователей: токены API создаёт и видит только админ.

## 1. Учётки

`users` += `role` (`admin` | `user`, миграция: существующие — `admin`), `permissions` (JSON, см. §2), `disabled` (bool), `telegram_chat_id` (text, §4), `notify_events` (JSON, §4).

«Настройки → Пользователи» (`/settings/users`, только админ): список (логин, роль, 2FA вкл/выкл, последний вход, выключен), «Добавить пользователя» (логин + временный пароль, роль, права),
правка: роль, права, «Выключить» (входить нельзя, сеансы завершаются), «Сбросить пароль» (новый временный), «Сбросить 2FA», «Удалить» (с подтверждением; сеансы и привязка Telegram удаляются, подписки остаются).
Ограничения: нельзя выключить, удалить или разжаловать последнего активного админа; нельзя удалить себя.

CLI: `dublyarr reset-password [--user <логин>] [--disable-2fa]` — без `--user` — первый админ (как сейчас).

## 2. Права пользователя

| Право (`permissions.*`) | Что разрешает | По умолчанию |
|---|---|---|
| `subscribe` | подписаться, изменить подписку, отписаться | вкл |
| `search` | ручной поиск, «Скачать», «Обновить» поиск, «Обновить из TMDB», тип сериал/аниме | вкл |
| `answer` | «Это он / Не тот сериал», «Назначить студию», нумерация аниме, варианты студий от Laya | вкл |
| `downloads` | «Активность»: пауза, продолжить, убрать, «Искать сейчас» | выкл |
| `storage` | «Хранилище», удаление сериала/файлов, подтверждение уборки и старых копий, исключения хранения | выкл |

Всегда (без прав): «Сегодня», «Библиотека», «Календарь», «Поиск и тренды», карточки, «Активность» (просмотр).
Админ — все права. Без права кнопка не показывается, а действие на сервере отвечает «Недостаточно прав» (проверка — в каждом server action и странице, не только в интерфейсе).
«Требует внимания»: вопросы о раздачах («Сомнительное совпадение», «Неизвестная студия», финальная проверка) — только с правом `answer`; уборка, старые копии, «Не задана папка» — только админу/`storage`.

## 3. Настройки

Пользователь видит в «Настройках» (и в «Ещё» на телефоне) только «Уведомления» и «Безопасность»; остальные разделы — `404` для него.
«Безопасность» пользователя: свой пароль, своя 2FA, свои сеансы; блока API нет. Админ видит всё, плюс «Пользователи».
Первый запуск (`/setup`) — только пока нет ни одной учётки (как сейчас); создаёт админа.

## 4. Уведомления

Бот Telegram один: токен, прокси — у админа («Уведомления» админа как сейчас + привязка своего чата).
У каждого (и у админа) — свой чат (привязка кодом, `users.telegram_chat_id`) и свои события (`users.notify_events`, по умолчанию как сейчас).
Пользователь в «Уведомлениях» видит только: привязать/отвязать свой чат (кодом), выбрать события, «Отправить тестовое».
Отправка: событие пишется в очередь как сейчас; доставка — каждому привязанному получателю, у кого событие включено
(вопросы `ask` — только с правом `answer`). Повторы и «не доставлено» — по получателю (`notification_deliveries`).
Кнопки в Telegram («Это он», «Не тот») — принимаются только из привязанного чата пользователя с правом `answer`; ответ записывается от его имени.
Миграция: `app_settings['telegram'].chatId` → `telegram_chat_id` первого админа; `telegram.events` → его `notify_events`.

## 5. Подписки

`subscriptions.added_by` (user id, null — до этой версии). Карточка сериала/фильма: «Подписка · добавил Аня». Ответы пользователей
(примеры для Laya) — как сейчас, без автора.

## Ошибки и крайние случаи

- Выключенный пользователь: вход — «Учётка выключена», активные сеансы завершаются сразу.
- У пользователя отобрали право — следующий запрос к действию отвечает «Недостаточно прав»; открытая страница — без кнопок после обновления.
- Удалили пользователя, который добавлял подписки — подпись «добавил (удалён)».
- API (`/api/v1`) — только токены админа; токены создаёт только админ (как сейчас).

## Тесты

Unit: права (по умолчанию, админ — все, проверка `can`), ограничения админа (последний админ, сам себя), выключение (вход, сеансы),
каждое защищённое действие отказывает без права, фильтр «Требует внимания», доставка уведомлений нескольким получателям (события, право `answer`, повторы по получателю),
кнопки Telegram от чужого чата и без права, миграция (роль, чат и события админа), CLI `--user`.
E2E (`14-users`): админ создаёт пользователя с правом только `subscribe` → пользователь входит (смена временного пароля не требуется) → видит в настройках только «Уведомления» и «Безопасность»,
подписывается, в ручном поиске нет «Скачать» (и прямой POST действия — отказ) → админ выключает его → вход запрещён.
