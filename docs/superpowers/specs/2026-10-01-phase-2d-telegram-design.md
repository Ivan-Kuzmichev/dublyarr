# Фаза 2d «Telegram»: дизайн

Последняя часть фазы 2 (2a → 2b → 2c → **2d Telegram**). Источник правды — `docs/spec.md` §12 (события), §3/§13 (вопросы пользователю), CLAUDE.md (секреты);
макет — `Settings.dc.html`, раздел «Уведомления».

## Цель

Dublyarr сообщает в Telegram о важном и принимает ответы на вопросы «тот ли это сериал» кнопками прямо в сообщении.

## Решения

- Доступность Telegram с NAS неизвестна (ответ владельца) → необязательный **прокси** (по умолчанию — прокси TMDB, если задан), «Отправить тестовое» показывает, есть ли связь.
- Только long-polling (`getUpdates`) — NAS за NAT, вебхука нет.
- Деструктивные подтверждения (старые копии, уборка) из Telegram **не выполняются** — только кнопка-ссылка на страницу со списком (CLAUDE.md: первое срабатывание — экран подтверждения).

## 1. Настройки и привязка

`app_settings['telegram']` (зашифровано): `{ token, chatId?, proxy?, baseUrl? }`; `app_settings['telegram.events']`: включённые события
(по умолчанию: `downloaded`, `stuck`, `ask`, `source-down` — вкл., `original` — выкл.).
Токен входит в адрес запроса (`/bot<token>/…`) — адрес и тексты ошибок маскируются (`bot***`), токен не пишется в лог.

Привязка: «Привязать чат» → одноразовый код из 6 цифр (живёт 10 мин, `app_settings['telegram.pairing']`) → пользователь отправляет его боту →
воркер (`telegram.poll`) видит сообщение с кодом → `chatId` сохраняется, боту уходит «Чат привязан». Поле Chat ID можно заполнить и вручную.
Сообщения и нажатия кнопок из других чатов игнорируются.

## 2. Очередь сообщений

Таблица `notifications`: `id`, `key` (уникальный — от повторов, например `import:42`), `kind`, `text`, `buttons` (JSON: строки кнопок `{ text, data? , url? }`),
`ref` (JSON для ответа: например `{ releaseId, titleId }`), `created_at`, `sent_at`, `message_id`, `attempts`, `next_at`, `error`.
`notify(db, { key, kind, text, buttons?, ref? })` — вставка, если событие включено (`kind` → переключатель) и ключа ещё нет.
Воркер `telegram.send` раз в 15 с: неотправленные с `next_at ≤ now` → `sendMessage`; ошибка → `attempts++`, `next_at = now + min(2^attempts мин, 1 ч)`;
старше суток — `error = 'не доставлено'`, больше не пытаемся. Без токена или чата — ничего не шлём (очередь копится не больше суток).

## 3. События (spec §12)

| Событие | Переключатель | Когда | Текст |
|---|---|---|---|
| Скачана новая серия | `downloaded` | загрузка импортирована (`syncDownloads`) | «📥 Игра престолов · S01E03 — LostFilm 1080p» (несколько: «S01E01–E03»); с `note` улучшения — «Улучшено: 1080p → 2160p» |
| Новый сезон (заметки 2b) | `downloaded` | `addNotice` | текст заметки |
| Загрузка застряла | `stuck` | загрузка впервые стала `stalled` | «⏳ Застряла: … — нет сидов больше суток» |
| Раздача пропала | `stuck` | синхронизация пометила `removed` (торрент исчез из клиента не по кнопке Dublyarr) | «⚠️ Раздача пропала из qBittorrent: …» |
| Нужно подтверждение | `ask` | у серии впервые появился `wanted_state = ask` | «❓ Игра престолов · S01E03: <причина>\n<заголовок раздачи>» + кнопки «Это он» / «Не тот сериал» (+ «Открыть», если задан адрес) |
| Старые копии / уборка ждут подтверждения | `ask` | появилась сводка (2b/2c) | текст + кнопка-ссылка (если задан адрес) |
| Вышел оригинал, озвучки нет | `original` | у серии впервые `wanted_state = waiting` | «🕐 Вышла S01E04 в оригинале · HDrezka ≈ 2 октября» |
| Источник не отвечает | `source-down` | источник не отвечает > 1 ч (`sources.failing_since`) | «🔌 Jackett не отвечает с 14:20: <ошибка>»; восстановление — «✅ Jackett снова отвечает» |

Для вопроса «тот ли сериал» серия помнит раздачу: `wanted_state.release_id` (пишется из вердикта `ask`).

## 4. Ответы кнопками

`callback_data` — `m:<notificationId>` / `r:<notificationId>` (≤ 64 байт). Воркер `telegram.poll` раз в 15 с: `getUpdates(offset)`;
сообщение с кодом привязки — привязка; `callback_query` из привязанного чата: по уведомлению берётся `ref` →
`addRule(titleId, trackerName, title, 'match' | 'reject')` (те же правила, что «Это он» / «Не тот сериал» в ручном поиске) → поиск сериала в очередь (`subscriptions.search-title`) →
`answerCallbackQuery` («Отмечено») и правка сообщения: кнопки убираются, добавляется «✓ Это он» / «✗ Не тот сериал». Уже решено (правило есть) — «Уже решено». `offset` хранится в `app_settings`.

## 5. Экран «Настройки → Уведомления»

Карточка «Telegram-бот»: токен (пароль, «сохранён — оставьте пустым»), «Проверить» (`getMe` → «@имя_бота»), прокси, адрес Dublyarr,
Chat ID + «Привязать чат» (показывает код и инструкцию; статус «Чат привязан: <имя>»), «Отправить тестовое». Карточка событий — 5 переключателей по макету.
Последние 10 уведомлений с состоянием (отправлено / в очереди / не доставлено).

## Ошибки и крайние случаи

- Telegram недоступен — очередь копится и отправляется позже; в статусах сервисов не участвует.
- Бот заблокирован пользователем (403) — `error`, без повторов этого сообщения; в настройках — «бот заблокирован».
- Нажатие по старому сообщению после перезапуска — данные в БД, ответ работает.
- 429 от Telegram — ждать `retry_after`.

## Тесты

Unit: клиент (методы, маскировка токена в ошибках, 429), очередь (ключ, повторы, «не доставлено», выключенные события), каждое событие на своём месте,
ответы кнопками (правило, правка сообщения, чужой чат, «уже решено»), привязка кодом (верный/неверный/просроченный).
E2E: заглушка Telegram Bot API (`tests/e2e/telegram-stub.mjs`, порт 3196) → настройки → привязка кодом → тестовое → вопрос по сомнительной раздаче → нажатие «Не тот сериал» → правило в ручном поиске.
