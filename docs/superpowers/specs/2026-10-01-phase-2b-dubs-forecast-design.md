# Фаза 2b «Озвучки и прогноз»: дизайн

Вторая часть фазы 2 (2a надёжность → **2b озвучки и прогноз** → 2c расписание и уборка → 2d Telegram).
Источник правды — `docs/spec.md` §1 (флаги подписки), §8 («Старая копия после улучшения»), §9 (прогноз), §11 (новые сезоны); здесь — как делаем.

## Цель

Dublyarr знает, через сколько дней после эфира каждая студия обычно выпускает серию, и показывает прогноз; меняет серию на озвучку выше по приоритету
и на целевое качество; старую копию удаляет по правилу (первый раз — с подтверждением); сам расширяет подписку на новые сезоны.

## Решения владельца

- Старая копия после замены — **удалять сразу**, первое срабатывание правила — **через подтверждение** (CLAUDE.md, spec §8).
- Улучшение качества — **да, до целевого** качества подписки, выше не поднимаем.
- Новый сезон при включённом «подписаться на новый сезон» — **сразу**, с заметкой.

## Что не входит

- Варианты правила «через 3 дня» / «при уборке», экран «Хранилище», остальные правила хранения — фаза 3.
- Спин-оффы и продолжения (TMDB не связывает сериалы) — решается в 2d вместе с уведомлениями.
- Частота поиска «чаще в день прогноза» — 2c (использует прогноз из 2b).

## 1. Наблюдения «студия выпустила серию»

Таблица `studio_sightings`: `title_id`, `studio_id`, `season`, `number`, `seen_at` (мс), `basis` (`seen` — увидели в поиске сами, `published` — по дате публикации на трекере),
`from_pack` (раздача — пак). Уникально (`title_id`, `studio_id`, `season`, `number`); при повторе остаётся более ранняя дата (и её `basis`), `from_pack` — `false`, если хоть раз видели отдельной серией.

Заполняется после каждого `searchTitle` из его раздач: только `match.level = 'match'`, только распознанные студии (`parsed.dubs[].studioId`), серии — из `parsed.episodes`
(пак без диапазона — все серии этого сезона по TMDB, у которых есть дата эфира), сезон — `parsed.seasons` (один). Дата — `min(firstSeenAt, publishedAt)`; `basis = published`, если взята `publishedAt`.
Раздачи, найденные до 2b, — один проход при первом запуске воркера (флаг `app_settings['sightings.backfilled']`).

## 2. Задержка студии и прогноз

`studioDelays(db, titleId)` → по каждой студии: задержки в днях `seen_at − air_date` (только ≥ 0 и серии с датой эфира), **медиана** (округление до 0,5 дня), число серий и основание:
- есть наблюдения отдельных серий с `basis = seen` → «по N сериям» (N — их число);
- иначе есть отдельные серии с `basis = published` → «≈ по датам раздач»;
- иначе только паки → «только паки»;
- нет наблюдений → «нет данных».
Медиана считается по лучшему доступному классу (отдельные `seen` → отдельные `published` → паки).

`forecastEpisode(ctx, ep)` для вышедшей серии, которая ждёт озвучку: по каждой позиции профиля-студии — ожидаемая дата `air_date + медиана` (нет данных — нет даты),
наблюдённая задержка (если серия у студии уже вышла); итог — ближайшая ожидаемая дата первой позиции с данными; строка запасного варианта из окон профиля:
«Если HDrezka не выйдет до пт — возьму LostFilm, потом заменю» (следующая позиция и дата, когда она откроется; «Любая» — «любую»; если запасной нет — «Жду только RuDub — запасная озвучка не задана»).

## 3. Где виден прогноз

- **«Сегодня» → «Ждём озвучку»** (`Main.dc.html`, `Mobile.dc.html`): справа «≈ 2 октября» / «≈ сегодня» / «≈ завтра»; полоска — доля прошедшего от эфира до прогноза, засечка — когда откроется запасная;
  под ней «Оригинал 29 сент» и «HDrezka обычно +1 день»; строка запасного варианта. Нет данных — «прогноза нет» без полоски.
- **«Календарь»**: пунктирные янтарные плашки «HDrezka ≈ +1 д» на ожидаемую дату для серий, которые ждут озвучку.
- **Карточка сериала** (`Series.dc.html`): колонки по студиям профиля (до 3): скачана/вышла у студии — «+1д» (светлая заливка), ожидается — пунктир с датой «сег.» / «пт» / «3 окт»,
  иначе «—»; блок «Скорость озвучки»: студии профиля и наблюдённые — «+1,1 дня» / «нет данных», полоска относительно самой медленной.
- **Окно подписки** (`Subscribe.dc.html`): у студий в профиле — основание («по 12 сериям» / «≈ по датам раздач» / «только паки» / «нет данных»).

## 4. Замена на лучшую версию

`episode_files` получает `dub_position` (позиция профиля, по которой взята; `null` — неизвестна), `downloads` — тоже `dub_position` (передаётся при старте и переходит в файл при импорте).

Кандидаты на замену при поиске по подписке — скачанные серии, у которых `air_date` не старше 30 дней и:
- `dub_position > 0` и включено «заменить, когда выйдет озвучка выше по приоритету», или
- `resolution` ниже целевого качества подписки.

Лучше, если раздача (вердикт `ok`, с учётом окон ожидания профиля): позиция строго выше; или та же позиция и разрешение больше текущего, но не выше целевого.
Из лучших — первая по рейтингу вердиктов. Качается обычным путём (`startRelease`, `kind` по раздаче); в «Активности» — «Улучшение: LostFilm → HDrezka» или «Улучшение: 1080p → 2160p».
Серия в замене не считается «нужной» (статусы `wanted_state` её не трогают); в карточке — «Скачана» + «улучшается».

## 5. Старая копия после улучшения

При импорте новой копии серии, у которой уже есть файл с другим путём (или тем же — тогда сначала переносим старый):
- правило подтверждено (`app_settings['retention.oldCopy.confirmed'] = true`) → старый файл удаляется из медиатеки;
- не подтверждено → старый файл переносится в `{media}/.dublyarr-old/<тот же относительный путь>` (переименование; не вышло — копия + удаление исходника не делается, остаётся на месте и пишется ошибка),
  запись в `old_copies` (`id`, `title_id`, `season`, `number`, `path` — относительный путь в скрытой папке, `size`, `reason` — «LostFilm → HDrezka», `created_at`).
«Требует внимания» на «Сегодня»: «Старые копии после улучшения: N · X ГБ» → страница `/old-copies`: список с галочками (по умолчанию все), итог «освободится X ГБ»,
кнопки «Удалить отмеченные» и «Оставить все». «Удалить» — удаляет отмеченные, ставит флаг подтверждения; дальше правило работает само, а оставшиеся (неотмеченные) копии остаются в скрытой папке
и списке. «Оставить все» — ничего не удаляет, флаг не ставит (список остаётся).
Удаление — только файлов внутри `{media}/.dublyarr-old` и только тех, что записаны в `old_copies`/`episode_files` как старая копия; путь проверяется на выход за пределы медиатеки.

## 6. Новые сезоны

`subscriptions.max_season` — последний сезон, на который распространяется подписка (`null` — без границы; при подписке = номер последнего сезона в TMDB, у существующих подписок — тоже).
`wantedEpisodes` и отбор паков учитывают её. После каждого `syncTitle` подписанного сериала: появился сезон с номером > `max_season` →
если включено «подписаться на новый сезон» — `max_season` = новый номер и заметка «Подписался на 3-й сезон»; иначе — заметка «Вышел 3-й сезон — подписка его не включает».
Таблица `notices` (`id`, `title_id`, `kind`, `text`, `created_at`); на «Сегодня» — блок «Новости» с заметками за 3 дня (в 2d те же события уйдут в Telegram).

## Ошибки и крайние случаи

- Медиана по одной серии — показывается, основание «по 1 серии».
- Отрицательная задержка (раздача раньше эфира по TMDB) — не учитывается.
- Замена не скачалась (ошибка, застряла) — старая копия не трогается, серия остаётся «Скачана».
- Импорт новой копии не удался — старая не трогается.
- Скрытая папка на другом томе невозможна (внутри медиатеки), переименование атомарно.

## Тесты

Unit: наблюдения (ранняя дата, `basis`, паки, только `match`), медиана и основания, прогноз и строка запасного варианта, отбор кандидатов и «что лучше», перенос в скрытую папку /
удаление после подтверждения / защита путей, расширение подписки и заметки, данные экранов. E2E: заглушки — «запасная озвучка вышла раньше, приоритетная позже» → замена →
«Требует внимания» → страница старых копий → «Удалить отмеченные» → старой копии нет, новая — в медиатеке.
