# Версия 2.1 «API, диагностика, источники»: дизайн

Доработка после первой установки 2.0 на NAS. Пять частей: диагностика и логирование, API с токенами,
типы источников (Jackett / JacRed / Torznab), картинки на «Сегодня», торренты, оставшиеся на паузе.
Цель всего, кроме картинок, — чтобы проблемы можно было найти и разобрать удалённо (владелец или Claude через API).

## Решения владельца

- API — чтение **и** изменение, переключатель «API включён», доступ **только из локальной сети**.
  NAS снаружи открыт через Pangolin (туннель Newt) — запросы через него локальными не считаются.
- Логирование — раздел «Настройки → Диагностика», выбор того, что логировать; главное — чтобы по логам можно было отладить проблему.
- Источник: вводится адрес Jackett, путь Torznab Dublyarr дописывает сам. Новый тип источника — **JacRed** (jac.red и свои установки).
- «Новые серии» на «Сегодня» — кадр серии вместо обрезанного постера.

## Что не входит

- Изменение «Безопасности» через API (пароль, 2FA, сеансы, токены, переключатель API).
- Удаление файлов в обход правил хранения: API запускает те же правила, первое срабатывание по-прежнему ждёт подтверждения на экране.
- Метрики и графики (Prometheus и т. п.).

## 1. Логирование

**Области** (`LogArea`): `qbit`, `search` (источники и запросы), `parse` (разбор и вердикты), `downloads` (выбор раздачи, загрузки, синхронизация),
`import` (импорт и пересборка), `tmdb`, `storage` (хранение, уборка, диск), `laya`, `telegram`, `worker` (задачи), `auth`, `api`, `system` (старт, миграции, процессы).

**Настройка** `app_settings['logging']`: `{ level: 'info', areas: Partial<Record<LogArea, 'debug' | 'info' | 'warn' | 'off'>> }` —
область без своей настройки берёт общий уровень. По умолчанию — `info` везде. `LOG_LEVEL` из env — только начальное значение, пока настройки нет.
Процессы перечитывают настройку раз в 10 с (сменилась — уровни логгеров меняются без перезапуска).

**Код**: `logger(area)` из `src/lib/log.ts` — дочерний логгер pino с полем `area`; redact секретов — как сейчас, `redactUrl` для адресов.
Существующие вызовы `log.*` переходят на области. Добавляются записи (`debug`, если не сказано иное):
- `qbit` — каждый вызов WebAPI: метод, хэши, код ответа, время; ошибки — `warn`.
- `search` — запрос к источнику: источник, строка, категории, число результатов, время; сбой/429 — `warn`.
- `parse` — по сериалу за проход: сколько раздач, сколько подошло, причины отказа (сводка) и лучшая раздача.
- `downloads` — решение «что качать» по серии (план, причина ожидания), каждая смена состояния загрузки `from → to` с причиной — `info`,
  выбор файлов в паке (какие индексы включены), запуск, перезапуск (§5) — `info`.
- `import` — шаги импорта, команды ffprobe/mkvmerge (без секретов), результат — `info`.
- `tmdb` — запросы (путь, код, время); `laya` — вопрос (задача, ключ), ответ, p, время; `telegram` — отправка/получение (без токена).
- `worker` — старт/конец задачи, длительность, ошибка — `info`/`warn`. `auth` — вход, неудачный вход, выход — `info`. `api` — метод, путь, токен (имя), код, время — `info`.

**Файлы**: дочерние процессы (Next, воркер, laya-serve) пишут JSON-строки в stdout, супервизор пишет их в `/data/logs/dublyarr.log`
и дублирует в свой stdout (видно в `docker logs`). Ротация — по 10 МБ, хранить 5 файлов (`dublyarr.log`, `.1` … `.4`). Строки laya-serve, не JSON, оборачиваются в `{ area: 'laya', msg }`.

## 2. Диагностика (`/settings/diagnostics`)

- **Логирование**: общий уровень, у каждой области — «как общий / подробно / обычно / только предупреждения / выкл.»; сохранение — сразу действует.
- **Журнал**: последние 500 строк (новые сверху) с фильтром по уровню, области и тексту; «Скачать логи» — текущий и ротированные файлы одним `.log` (в отдельном окне, без сжатия).
- **Сверка с qBittorrent**: живые загрузки Dublyarr рядом с тем, что говорит клиент: состояние, прогресс, число включённых файлов;
  расхождения подсвечены («у нас качается, в клиенте остановлен», «в клиенте нет торрента», «все файлы выключены»).
- **Сервисы и задачи**: воркер, Laya, qBittorrent — работает / нет (по отметкам сервисов); по каждому типу задачи воркера — последний успешный запуск, последняя ошибка, сколько в очереди. Перезапуски процессов видны в журнале (область `system`).

Телефон — одна колонка, журнал — карточки строк.

## 3. API

**Включение**: «Настройки → Безопасность» — переключатель «API включён» (`app_settings['api']`, по умолчанию выкл.) и токены:
создать (имя → токен показывается один раз), список (имя, первые символы, создан, последнее использование и адрес), отозвать.
Таблица `api_tokens`: `id, name, hash (sha256), prefix, created_at, last_used_at, last_ip`. Токен — `dy_` + 32 байта base64url.

**Доступ**: `Authorization: Bearer <токен>` на `/api/v1/*`. Отказ — `401` (нет/неверный токен), `403` (API выключен или запрос не из локальной сети).
Локальная сеть: адрес клиента и **все** адреса в `X-Forwarded-For` / `X-Real-IP` / `Forwarded` — частные
(`127/8, 10/8, 172.16/12, 192.168/16, 169.254/16, ::1, fc00::/7, fe80::/10`, включая `::ffff:`-формы).
Next.js сам ставит `X-Forwarded-For` = адрес сокета, если заголовка нет; Pangolin передаёт внешний адрес клиента — такой запрос получает `403`.
Сеансовый cookie на `/api/v1` не действует (только токен). Все ответы — JSON, ошибки `{ error: 'текст' }`.

**Чтение**:
- `GET /status` — версия, сервисы, задачи воркера, qBittorrent/источники/TMDB/Telegram/Laya (доступность), диск.
- `GET /logs?lines=&level=&area=&q=&since=` — строки журнала.
- `GET /downloads?state=` — загрузки Dublyarr; `GET /downloads/:id` — с файлами и состоянием в qBittorrent; `GET /qbit/reconcile` — сверка (§2).
- `GET /library`, `GET /titles/:kind/:tmdbId` — карточка: подписка, сезоны и серии со статусами, файлы.
- `GET /wanted` — нужные серии и почему не качаются; `GET /attention` — «Требует внимания»; `GET /activity?limit=` — история.
- `GET /titles/:kind/:tmdbId/releases?s=&e=` — ручной поиск (опрашивает источники, как экран).
- `GET /sources`, `GET /settings/:section` — настройки (секреты — только «задан / не задан»).

**Изменение**:
- `POST /titles/:kind/:tmdbId/subscription` (создать/изменить, профиль проверяется как в форме), `DELETE …/subscription?files=`.
- `POST /titles/:kind/:tmdbId/search` — искать сейчас; `POST /titles/:kind/:tmdbId/refresh` — обновить из TMDB.
- `POST /releases/:id/download` (как «Скачать» в ручном поиске), `POST /releases/:id/answer` `{ match: true|false }`, `POST /releases/:id/studio`.
- `POST /downloads/:id/(pause|resume|remove|retry)`.
- `PATCH /settings/:section` — разделы, кроме «Безопасности», ключа TMDB и бота Telegram (их привязка — только в интерфейсе); пароль qBittorrent — только запись. `POST /sources`, `PATCH /sources/:id`, `POST /sources/:id/test`.
- `POST /jobs/:name` — поставить задачу (`subscriptions.search`, `downloads.sync`, `cleanup.run`, `retention.run`, `tmdb.refresh-all`, `laya.train-now`).

Обработчики вызывают те же функции `src/lib/*`, что и server actions (никакой второй логики). Каждый запрос — запись в журнал (`api`).

## 4. Источники

`sources.kind`: `jackett` | `jacred` | `torznab` (миграция: существующие — `torznab`, адрес Jackett-вида распознаётся и переводится в `jackett`).
Форма: выбор типа → поля.
- **Jackett**: адрес (`http://192.168.1.10:9117`) + API-ключ. Запросы — `{адрес}/api/v2.0/indexers/all/results/torznab/api`; список трекеров — `t=indexers` (как сейчас).
  Вставлен полный адрес Torznab — лишний путь отрезается.
- **JacRed**: адрес (по умолчанию `https://jac.red`) + ключ (необязательно, для своих установок). Поиск — JSON `GET {адрес}/api/v1.0/torrents?search=<строка>`
  (поля `tracker`, `url`, `title`, `size`, `createTime`, `sid`, `pir`, `magnet`, `types`). Хэш — из magnet, топик — `url`, трекер — `tracker`
  (регистрируется при первом появлении, роли основной/запасной — как у остальных). Фильтр вида — по `types` (`movie`/`tvshow`/`anime`…), вместо категорий Torznab.
  Раздачи — только magnet (выбор файлов после метаданных — уже есть). Вежливость: запросы к одному JacRed — по одному, пауза ≥ 1 с; `429` — одна пауза по `Retry-After` (≤ 10 с), затем «не ответил».
- **Torznab**: полный адрес (Prowlarr и прочее) + ключ — как сейчас.

Проверка источника («Проверить») — по типу: Jackett — `t=caps`, JacRed — поиск-пустышка (`search=test`), Torznab — `t=caps`.
В интерфейсе слово «Torznab» остаётся только у третьего типа.

## 5. Торренты на паузе

Что видно в qBittorrent владельца (категория `dublyarr`): пак «Bookish / Книжный» — 0 Б, у всех 12 файлов приоритет 0, клиент считает его «готовым»;
ещё две раздачи остановлены на 6 % и 25 %. Точная причина по текущим логам не восстанавливается — потому §1–2. Известные слабые места:
- `/torrents/add` в qBittorrent 5 асинхронный: «старт» и выбор файлов сразу после добавления могут прийти до появления торрента и молча не сработать;
- если в клиенте торрент остановлен, синхронизация только переводит загрузку в «паузу» — никто её не запускает снова;
- включённые файлы после выбора не перепроверяются.

Изменения:
- после `add` — ждать появления хэша в клиенте (опрос раз в 0,5 с, до 15 с); не появился — ошибка загрузки «qBittorrent не добавил торрент».
- после выбора файлов и старта — перечитать файлы: нужные включены, торрент не остановлен; нет — повторить один раз, иначе ошибка с причиной.
- пауза пользователем (кнопка «Пауза», API) — флаг `downloads.paused_by_user`. Синхронизация: загрузка не завершена, в клиенте остановлена,
  не пауза расписания/переполнения и не пользователя → запуск заново (`info`-запись «перезапуск»); больше 3 перезапусков за час — ошибка «qBittorrent останавливает загрузку».
- пак/фильм, у которого в клиенте все файлы выключены, а нужные серии не скачаны, — заново выбрать файлы (`selectAndStart`).

## 6. Картинки на «Сегодня»

`episodes.still_path` (миграция; заполняется при синхронизации сезона из TMDB `still_path`). Карточка «Новые серии»: кадр серии → фон сериала (`backdrop`) → постер.
В `IMAGE_SIZES` добавляется `w300` (размер кадров и фонов TMDB); карточка — `w300`, на широких экранах — `w780`.

## Ошибки и крайние случаи

- Нет прав на запись в `/data/logs` — логи только в stdout, на «Диагностике» — «Журнал недоступен: …».
- Журнал больше 50 МБ не бывает (ротация); `GET /logs` читает с конца и отдаёт не больше 2000 строк.
- API выключен — все `/api/v1/*` → `403` без проверки токена (ничего не пишется в `last_used_at`).
- JacRed не отвечает / 429 — как сбой источника (уведомление «не отвечает больше часа» — как у остальных).

## Тесты

Unit: области и уровни логгера (настройка, перечитывание, `off`), ротация файла, разбор журнала с фильтрами;
локальная сеть (частные адреса, `::ffff:`, цепочка `X-Forwarded-For`, внешний адрес от прокси), токены (создание, хэш, отзыв, выключенный API, 401/403);
обработчики API (чтение и изменение вызывают те же функции, «Безопасность» недоступна); источники (нормализация адреса Jackett, миграция, JacRed: разбор ответа,
хэш из magnet, виды, пауза и 429); торренты (ожидание появления, перепроверка файлов, перезапуск остановленной, флаг пользователя, лимит перезапусков,
пак с выключенными файлами); картинки (кадр → фон → постер).
E2E (`13-api-diagnostics`): включить API и создать токен → `GET /api/v1/status` с токеном → «Диагностика» показывает запись `api`;
источник Jackett по адресу без пути находит раздачи (заглушка отвечает по пути Jackett).
