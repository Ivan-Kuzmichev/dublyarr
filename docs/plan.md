# План разработки

После фаз 0–1 должна получиться рабочая замена текущему Dublyarr. Остальное — поверх.
Каждая фаза заканчивается рабочим образом Docker, который можно поставить на NAS.

## Фаза 0. Фундамент
- Next.js + TypeScript, линтер, тесты (unit для парсера и правил — обязательно).
- Дизайн-токены и базовые компоненты из `design/` (кнопки, сегменты, карточки, таблицы, боковая и нижняя навигация).
- Dockerfile: Node + Python + MKVToolNix + ffprobe; точка входа запускает Next.js, воркер и laya-serve (пока можно заглушкой).
- SQLite + миграции; хранение секретов.
- Вход: пароль + TOTP + резервные коды + сеансы.
- Нарисовать и сделать: первый запуск, «Безопасность».

## Фаза 1. Ядро
- TMDB: поиск, карточки, сезоны, даты; тип сериал/аниме/фильм.
- Подписки и профили по умолчанию (spec §1).
- Источники: несколько Torznab, параллельный опрос, дедупликация, основной/запасной (spec §2).
- Парсер + словарь студий + оценка совпадения (spec §3). Покрыть тестами на реальных заголовках.
- Загрузка через qBittorrent в порядке «текущий пак → серия → пак с выбором файла» (spec §4); импорт по шаблону имени.
- Экраны: Сегодня, Библиотека, Карточка сериала, Подписка, Активность + ручной поиск, Календарь;
  настройки: Источники, Подписки и студии, Загрузка и папки.
- Нарисовать и сделать: Поиск и тренды.
- Миграция из текущей версии (если нужна — уточнить).

## Фаза 2. Автоматика
- Отслеживание обновлений паков по хэшу топика.
- Статистика задержек студий и прогноз (spec §9).
- Запасная озвучка, замена на приоритетную, автоподписка на новые сезоны (spec §11).
- Расписание опроса и скорости (spec §5), уборка в qBittorrent (spec §7), Telegram (spec §12).

## Фаза 3. Файлы и место
- Пересборка mkv, флаги дорожек, проверка ffprobe (spec §6).
- Правила хранения, исключения, первая уборка с подтверждением, экран «Хранилище», удаление сериала (spec §8).
- Фильмы (spec §10) + карточка фильма (нарисовать).

## Фаза 4. Laya
- Интеграция дочерним процессом, статус в настройках.
- Три задачи, порог уверенности, вопросы пользователю (spec §13).
- Сбор примеров, ночное дообучение, проверка «не хуже», версии и откат, поведение при обновлении.
- Экран «Дообучение» (desktop + mobile).
- Перед стартом: замерить скорость ответа Laya на CPU NAS.

## Как работать с Claude Code
- Одна фаза — одна ветка. Внутри фазы — небольшие задачи, каждая с тестами.
- Перед экраном — открыть его макет в `design/screens/` и сверить поведение со `spec.md`.
- Решения, принятые по ходу (ORM, структура БД, формат парсера), дописывать в `CLAUDE.md`.
